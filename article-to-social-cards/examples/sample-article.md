# 先搞清楚一件事

这个仓库不是一个应用，也不是一个框架。

**就是一堆配置文件。**

你要理解这件事：Claude Code 本身能力很强，写代码、查 bug、跑测试都行。但它有个问题——**没有记忆，没有习惯，没有上下文**。

每次打开，你都得重新告诉它：项目结构是什么、测试怎么跑、上次改到哪了、哪些文件不能碰。

你每天花15分钟重新交代这些背景信息，一个月就是 **7.5 小时**浪费在"让 AI 回忆你是谁"上面。

Affaan 做的事情就是把这些信息全部写成配置文件，让 Claude 启动时自动读取。

他的配置仓库包含：

| 类型 | 数量 | 作用 |
|------|------|------|
| Rules | 多语言 | 自动执行的行为规范 |
| Hooks | 4 种 | 事件触发的自动化 |
| Commands | 30+ | 斜杠快捷指令 |
| Skills | 30+ | 带经验的工作流 |
| Agents | 12 个 | 能独立干活的子代理 |

# 五层配置

他的体系分五层，我按从轻到重排。

**Rules** — 自动执行的规矩。你在文件里写"所有代码提交前必须跑测试"，Claude 就会照做，你不用每次提醒。比如测试规范、Git 工作流、安全编码，这些都可以写成 Rule。

**Hooks** — 事件触发器。用过 Git 的人知道 pre-commit hook，提交前自动跑检查脚本。Claude Code 的 Hook 是同一个逻辑：**会话结束自动保存进度，启动时自动加载上次状态**。后面会单独讲这个。

**Commands** — 快捷指令。打 /tdd 就进测试驱动流程，打 /verify 跑全套检查。Affaan 配了 30 多个，覆盖了从代码生成到部署的各种场景。

**Skills** — 带判断力的工作流。两者的区别用一个例子说最清楚：

| | Command | Skill |
|---|---------|-------|
| 你说 | "跑测试" | "跑测试" |
| Claude 做 | 执行测试命令 | 判断项目语言，选 cargo test 还是 pytest，覆盖率低于80%标红，碰到 flaky test 重跑两次再判定 |

Affaan 写了 30 多个 Skill，开发场景基本全覆盖。我自己也在学着写，目前主要用在内容创作流程上。

**Agents** — 能独立干活的子代理。你把一个问题扔给研究 Agent，它自己去查文档、读源码、写总结报告，不用你盯着。Affaan 配了 12 个，黑客松那天就是靠这 12 个 Agent 分工协作跑完全程的。

# 记忆：我配完最后悔没早配的功能

Claude Code 默认没有长期记忆。

你关了终端，上下文全没。明天打开，它不认识你了。

这个问题听起来小，实际非常磨人。我之前改一个部署配置改到一半，关了电脑去吃饭，回来重新描述了十几分钟上下文 Claude 才接上。那十几分钟里我在做的事情就是**人肉当数据库**。

Affaan 用两个 Hook 解决了这个问题：

| Hook | 触发时机 | 做什么 |
|------|----------|--------|
| **Stop** | 会话结束 | 自动把进度、未完成的事、关键决策存到文件 |
| **SessionStart** | 下次启动 | 自动加载上次存的文件 |

我配好之后第二天打开 Claude Code，它说"上次你改到第47行，DNS 那段还没加"。

**从"每次重新认识"变成"接着上次聊"。**

两个 Hook，半小时能配好。我配完之后最大的感受是：早该配了。

# 不重复犯错

Claude 有个毛病：**同一个错误它会反复犯**。

你纠正一次，这次会话里它记住了。下次新会话，忘了，又犯。

我碰到过一个特别烦的例子。我项目里用的是 pnpm，但 Claude 每次都默认跑 npm install，碰到 pnpm-lock.yaml 就开始报错。我纠正了三次，每次新会话它还是默认 npm。第四次的时候我真的很想摔键盘。

Affaan 的方案叫 **continuous learning**：

| 时机 | 动作 |
|------|------|
| 会话结束时 | 自动提取"犯了什么错、学到了什么"，存成文件 |
| 下次碰到类似情况 | Claude 先读这些记录，再动手 |

我照着他的思路也配了一个 continuous-learning skill。配了之后 pnpm 这种"反复纠正不住"的问题彻底消失了。

这个功能省的不是时间。**是你反复纠正同一个错误时积累的那种烦躁感**。

# 他在 README 里写的一句话

Affaan 在仓库的 README 里写过一段话：

**"投资模式，不要投资模型技巧。"**

prompt 技巧、temperature 参数、魔法提示词——这些东西换个模型版本就可能失效。你上个月调好的 prompt，这个月换了模型效果可能完全不一样。

但你花时间设计的工作流不会过期。

| 投资类型 | 生命周期 | 举例 |
|----------|----------|------|
| **模型技巧** | 一个版本 | prompt 模板、temperature 调参、特定模型的 hack |
| **工作流模式** | 跨模型通用 | 测试流程、记忆管理、代码审查规范 |

一套好的测试流程，底层换成 GPT 还是 Gemini 还是 Llama 都能用。一套好的记忆管理方案，换到 Cursor 换到 Windsurf 也能迁移过去。

**模型是消耗品。模式是资产。**

我看完这个仓库之后开始重新审视自己的配置，很多之前凭感觉弄的东西，现在有了更清晰的方向。

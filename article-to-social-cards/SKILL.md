# 长文转社媒图卡

## 作者与迭代

- **迭代者**：[@ai_xiaomu](https://x.com/ai_xiaomu)

把 Markdown 文章一键变成 1080×1440 的图文卡片,**小红书直接发图文笔记,抖音直接发图集**——两个平台共用同一套尺寸。

## 触发条件

用户说:
- 「生成小红书图文/长图」
- 「做抖音图文/图集」
- 「这篇文章发小红书」
- 「排版这篇文章」(在内容创作场景下)
- 「做封面 + 内页」

## 平台说明

**小红书** 和 **抖音图文** 用同一套图(1080×1440 尺寸通用):
- 小红书:发笔记 → 上传图片 → 全选刚导出的 PNG
- 抖音:发布 → 选「图文」/「图集」 → 上传同样的 PNG

不需要分两次做。一次出图,两个平台都能发。

## 工作流程(AI 必读,严格按顺序执行)

### Phase 1: 理解原始素材

1. 阅读用户给的文章/素材
2. 识别核心:主题、关键观点、数据、案例
3. 识别图片:截图、配图的路径

### Phase 2: 重写文章(不能跳过!)

**关键原则**:**不能**直接把用户的原始文章塞进来。必须针对小红书图文重写。

重写要求:

1. **内容丰富度**
   - 加干货细节,不要泛泛而谈
   - 用具体案例、数据、对比表格
   - 每个观点都要有支撑

2. **排版规划**(每页必须 >80% 填充)
   - 页面区域:1080×1440px,内容区约 920×1296px
   - 提前规划每页放什么
   - 图片页:标题 + 小标题 + 图片(图片约占 60-70% 高度)
   - 文字页:标题 + 正文 + 列表/表格

3. **分页策略**
   - 用 `---page---` 手动分页
   - 每页内容量要合适,不能太少(留白 >20% 是灾难)
   - 图片单独一页时,配上标题和简短说明

4. **图片处理**
   - 用相对路径:`![说明](images/xxx.png)`
   - 不要手动 base64,prepare.mjs 会自动处理

### Phase 3: 高点击率封面设计(核心!)

**封面决定点击率,是整篇文章最重要的部分。**

#### 三钩子原则(必须!)

封面必须有 **至少 3 个钩子**,且要 **尽可能大**:

| 钩子类型 | 作用 | 示例 |
|---|---|---|
| 权威钩子 | 建立信任 | 斯坦福、Anthropic、Google logo |
| 数字钩子 | 制造冲击 | 10x、3 个测试、2000 行代码 |
| 利益钩子 | 明确价值 | FREE、完整源码、看完你会知道 |

#### 封面公式

```
大标题(关键词高亮)
    ↓
权威背书条(机构名 + 一句话核心价值)
    ↓
数字卡片矩阵(3-6 个数字)
    ↓
价值预告(「看完这篇你会知道」列表)
    ↓
底部:作者 + 标签
```

#### 配色规范(固定,不要改)

| 元素 | 颜色 | 说明 |
|---|---|---|
| 主背景 | #FFFFFF | 纯白 |
| 主标题 | #1A1A1A | 深灰黑 |
| 高亮词 | #C41230 | 小红书红 |
| 正文/副标题 | #1A1A1A | 深灰黑 |
| 数字卡片背景 | #F5F5F5 | 浅灰 |
| 数字卡片强调 | #C41230 | 红色卡片(1-2 个对角放) |
| 价值预告背景 | #FEF2F2 | 浅红底 |

**禁用**:莫兰迪/暖灰米色(#faf8f5、#faf9f7 等)——视觉对比弱,信息流里不抓眼。

#### 标题公式(按点击率排序)

| 公式 | 示例 | 适用 |
|---|---|---|
| 身份反差 + 结果 | 硅谷大神 Kevin Rose / 不写代码的投资人 / 用 AI 造了个新闻编辑部 | **最高** |
| 权威 + 动作 + 热词 | 斯坦福开了一门教 vibe coding 的课 | 高 |
| 数字 + 动作 + 结果 | 一个人 48 小时用三家 AI 做了个几何可视化系统 | 中高 |
| 对比 + 悬念 | Claude vs Gemini｜AI 写代码谁更强 | 中高 |
| 痛点 + 解决方案 | 方案没聊透｜8 小时白干 | 中 |

**身份反差公式详解**(点击率最高):
- 第 1 行:权威身份(硅谷大神 XX、斯坦福教授 XX)
- 第 2 行:反差标签(不写代码的投资人、从没学过编程的设计师)
- 第 3 行:震撼结果(用 AI 造了个 XX)
- 高亮词用红色:权威身份 + 结果关键词
- 核心机制:认知失调 → 好奇心 → 点击

### Phase 4: 图片预处理

把文章里图片路径转换为压缩后的 base64:

```bash
cd ~/.claude/skills/article-to-social-cards && node prepare.mjs /tmp/article.md /tmp/article-final.md
```

这一步会:
- 读取所有图片文件
- 压缩为 WebP(quality 75,max-width 1600px)
- 替换为 base64 data URL(避免相对路径在 file:// 协议下失效)

### Phase 5: 生成 HTML

```bash
cd ~/.claude/skills/article-to-social-cards && node run.js \
  --markdown /tmp/article-final.md \
  --cover /tmp/cover.json \
  --output /tmp/output.html \
  --no-merge
```

参数说明:
- `--no-merge`:关闭自动合并(用手动 `---page---` 分页,**推荐**)
- 不加 `--no-merge`:自动合并短页面(懒人模式,容易出问题)

### Phase 6: 输出结果

告诉用户:
```
已生成排版文件:/tmp/output.html

请用浏览器打开:
1. 检查每一页有没有红色溢出警告
2. 点顶部「下载全部 PNG (ZIP)」一键打包
3. 解压后小红书/抖音直接上传
```

### Phase 7: 生成发布内容

为用户准备:
1. **标题**(吸引点击,包含搜索热词)
2. **正文**(摘要,有人味,不要 markdown 格式)
3. **标签**(覆盖主要搜索场景)
4. **初期评论**(3-5 条,引导互动)

## cover.json 完整格式

```json
{
  "title": "第1行标题\n第2行标题\n第3行标题",
  "highlightWords": ["红色高亮词1", "红色高亮词2"],
  "authorityBadge": {
    "name": "权威标签",
    "subtitle": "一句话说明核心价值"
  },
  "stats": [
    { "number": "2260", "label": "篇文章/天", "highlight": true },
    { "number": "4", "label": "个 AI 分工" },
    { "number": "16", "label": "维度自动评分" },
    { "number": "63", "label": "个信息源" },
    { "number": "17", "label": "个 Pipeline" },
    { "number": "1周", "label": "独立开发", "highlight": true }
  ],
  "valuePreview": {
    "title": "看完这篇你会知道",
    "items": [
      "<b>关键词</b> 说明文字",
      "<b>关键词</b> 说明文字"
    ]
  },
  "author": "你的小红书名",
  "status": "完整复刻中",
  "tags": ["标签1", "标签2", "标签3"]
}
```

注意事项:
- `title` 用 `\n` 换行,不要用标点分隔(冒号、逗号会直接显示出来)
- `highlightWords` 渲染为红色,选 2 个最有冲击力的词
- `stats` 建议 6 个(3×2 网格),`highlight: true` 的放第 1 个和第 6 个(对角)
- `valuePreview.items` 建议 3-4 条,关键词用 `<b>` 加粗
- `author` 不填则不显示作者行

## 排版具体规则(朋友的内容要按这个写)

### 每页内容量(实测)

| 页面类型 | 内容上限 | 实例 |
|---|---|---|
| 纯文字页 | 5-8 段落 | 「五层配置」那页(`---page---` 之间 5 段) |
| 表格 + 引子 | 1-3 段引子 + 1 个 ≤8 行表格 | 「记忆」那页(2 段 + 1 个 2 行 Hook 表) |
| 大表格独占 | 1 个标题 + 1 个 5-12 行表格 | 「五层配置」对比表那页 |
| 短陈述高潮 | 1-2 个加粗短句 + 简单收尾 | 「投资模式,不要投资模型技巧」那页 |

**判断标准**:写的时候不要单页超过 `~500 字`,超了就 `---page---` 分一下。生成 HTML 后浏览器顶部会自动检测溢出,溢出的页会红框显示,根据提示再调。

### 标题层级(每页只能有一个 h1)

| 写法 | 渲染 | 用途 |
|---|---|---|
| `# 标题` | h1 红色下划线 | 每页只用一个,做页面入口 |
| `## 标题` | h2 红色下划线 | 一页内分小节 |
| `### 标题` | h3 无下划线 | 子小节 |
| `**关键词**` | 红色加粗 | 段落里的重点词,自动变小红书红 |

**禁止**:
- 一页内多个 `#`(会有多个红色下划线,视觉混乱)
- 段落里用 `> 引用` 当装饰(blockquote 占两行,浪费空间)
- 三级嵌套列表(`-` 套 `-` 套 `-`,小红书页面装不下)

### 表格写法(很重要,实测最容易爆)

```markdown
| 列1 | 列2 | 列3 |
|---|---|---|
| 简短 | 简短 | 简短 |
```

- **列数 ≤ 3**:4 列以上手机屏幕看不清
- **每格内容 ≤ 15 字**:多了会换行,表格高度暴涨
- **行数 ≤ 8**:超过就拆成两个表格分两页

### 段落写法

- 句子可长,**段落要短**:一段最多 3-4 行
- 加粗用 `**` 包,只用 1-3 处,**不是越多越好**
- 引号一律用 `「」` 不要用 `""`(中文排印规范)

### 分页技巧

| 信号 | 动作 |
|---|---|
| 浏览器顶部出现红色 banner | 这页超 1440px 了,加 `---page---` |
| 页面右下角红色边框 | 同上 |
| 单页留白超过 20% | 内容太少,删掉这个 `---page---`,合并到前页 |
| 表格占满整页还溢出 | 表格行数减半,拆成两页 |

## 核心规则(每次必守)

1. **封面必须有 3 个钩子**:权威背书 + 数字冲击 + 价值预告,缺一不可
2. **钩子要尽可能大**:数字 64px,标题 76px,不要小气
3. **配色统一**:#C41230 + #FFFFFF + #F5F5F5,不要自创新色
4. **必须重写文章**:不能直接用原始素材,要针对小红书优化
5. **必须用 `--no-merge`**:手动分页比自动合并可控
6. **必须先 prepare.mjs 再 run.js**:不然图片路径在浏览器里失效
7. **输出文件放 `/tmp`**:不污染项目目录
8. **生成后必须看溢出警告**:浏览器打开 HTML,顶部会显示哪些页溢出了

## 常见问题(朋友最常踩的坑)

### Q1: 页面右下角红色边框/顶部红色 banner?
**症状**:浏览器打开 HTML 后看到红框、有「⚠ 内容溢出」的提示。
**原因**:这一页内容超过 1440px 边界,导出 PNG 后底部会被截断。
**解决**:在 markdown 里这一页中间加一个 `---page---` 把它分成两页。重新跑 run.js。

### Q2: 字体显示成宋体了,跟示例不一样?
**症状**:本来应该是粗黑体,显示成了细宋体。
**原因**:Google Fonts 没加载下来(国内网络/file:// 协议限制/防火墙)。
**解决**(三选一):
- 起本地 http server:`cd /tmp && python3 -m http.server 8000`,然后浏览器访问 `http://localhost:8000/output.html` 而不是 `file:///tmp/output.html`
- 等几秒再下载 PNG(字体加载慢,但通常能加载)
- 接受 fallback:run.js 已经配了 PingFang/苹方/微软雅黑/宋体 fallback,实在加载不到也是中文字体,只是没那么粗

### Q3: 图片不显示/裂图?
**症状**:浏览器里图片位置是个破图标。
**原因**:没跑 prepare.mjs 直接跑了 run.js,或用了 file:// 协议引用相对路径。
**解决**:先 `node prepare.mjs my-article.md my-article-final.md` 把图片转 base64,再 `node run.js --markdown my-article-final.md ...`

### Q4: 跑 `npm install` 报 sharp 装不上?
**症状**:`Error: Cannot find module @img/sharp-darwin-arm64`
**原因**:sharp 是 native binary,可能需要特定平台预编译版本。
**解决**:
- Mac M1/M2/M3:`npm install --include=optional sharp`
- Linux:`npm install --os=linux --cpu=x64 sharp`
- 实在装不上:用 Docker 或 Node 18+(更兼容)

### Q5: 超过 18 页怎么办?
**原因**:小红书单篇最多 18 张图。
**解决**:拆成上下篇,或精简内容(优先精简纯文字页,合并相邻短页)。

### Q6: 标题里出现冒号/逗号显示出来了?
**症状**:封面标题里能看到 `:` 或 `,` 字符。
**原因**:cover.json 的 title 用了标点。
**解决**:用 `\n` 换行,不要用标点。

### Q7: 我不知道该怎么写 cover.json?
**解决**:抄 `examples/sample-cover.json`。填什么有规律:
- title:3 行,第 1 行身份/事件,第 2 行反差/结果,第 3 行强化
- highlightWords:title 里 2 个最有冲击力的词
- stats:6 个数字,第 1 个和最后一个 highlight: true(对角红色)
- valuePreview:3-4 条「看完这篇你会知道」,关键词 `<b></b>` 加粗

### Q8: 内容写好了但封面不知道怎么数字化(没有真实的 stats)?
**原因**:数字封面适合事件型/盘点型/拆解型内容,不适合纯观点。
**解决**:换标题公式。把数字卡片改成 3 个,比如 `["核心观点1", "核心观点2", "核心观点3"]`——但这通常说明你的选题缺数据支撑,**重写选题**比换封面更对。
